# MeloNX UX 设计优化方案

> 版本：v1.0 · 日期：2026-08-18
> 范围：iOS / iPadOS 客户端全流程
> 目标：降低新手流失率、减少用户困惑、提升核心路径（导入 → 启动 → 游玩）转化率

---

## 1. 用户旅程地图（现状）

### 1.1 核心路径

```
首次启动
  └─ 模式选择（仅 iPhone）──┬─ 手柄模式（Remote Controller）
                            └─ 模拟器模式
                                 └─ 设置向导（动画 → Keys → Firmware → Finish）
                                      └─ 游戏库（空状态）
                                           └─ 导入游戏（+ 按钮）
                                                └─ 启动游戏（JIT 检查 → Loading → 游戏画面）
                                                     └─ 游戏内（HUD 菜单 / 虚拟手柄 / 设置）
```

### 1.2 痛点分布（按阶段）

| 阶段 | 主要痛点 | 严重度 |
|------|---------|--------|
| 模式选择 | 概念不清："手柄模式"与"模拟器模式"的区别没有解释，用户不知该选哪个 | 中 |
| 设置向导 | 动画无跳过感知、key 文件专业术语多、无错误恢复指引 | 高 |
| 游戏库 | 空状态引导弱、导入反馈弱（已修复）、JIT 状态不可见 | 高 |
| 启动游戏 | JIT 是最大拦路虎，失败原因不可见 | 高 |
| 游戏内 | 菜单入口隐藏（按钮透明度 0.4）、退出标记"Unstable"制造焦虑 | 中 |
| 设置 | 设置项 1500+ 行代码无分组可视化，专业术语无解释 | 低 |

---

## 2. 设计原则

1. **渐进式披露（Progressive Disclosure）**：默认只展示核心路径，高级选项折叠
2. **失败前置（Fail Early）**：JIT、内存、固件等前置条件在启动前可见、可诊断
3. **反馈即时性**：每个用户操作 500ms 内必须有视觉反馈
4. **术语降维**：模拟器专业术语（prod.keys、JIT、PTC）必须有用户语言解释
5. **动效一致**：所有转场使用统一时长与缓动，loading 状态必须可感知剩余进度

## 3. 优化项（按用户旅程排序）

### 3.1 模式选择页（AppModeRouterView）

| ID | 优化项 | 现状 | 方案 | 优先级 |
|----|--------|------|------|--------|
| M1 | **模式卡片化** | 两个按钮并排，无说明文字 | 改为两张可视化卡片：每张含图标、标题、一句话描述（"把 iPhone 变成手柄，配合 iPad/Mac 游玩" vs "在本机运行 Switch 游戏"） | P1 |
| M2 | **记住上次选择** | 每次冷启动都问 | 首次选择后写入 `MeloNXAppMode`（已实现），但在模式页增加"可在设置中随时切换"的提示 | P2 |
| M3 | **设备能力提示** | 无 | iPhone 12 以下设备选择模拟器模式时提示"您的设备可能无法流畅运行部分游戏" | P3 |

### 3.2 设置向导（SetupView）

| ID | 优化项 | 现状 | 方案 | 优先级 |
|----|--------|------|------|--------|
| S1 | **动画可跳过** | 启动动画期间无任何交互提示 | 动画播放 2 秒后显示"跳过"按钮；动画期间点击任意位置跳过 | P1 |
| S2 | **步骤进度指示** | 无进度概念，只有两个 setupStep | 顶部添加 3 步进度条：①导入 Keys ②安装固件 ③完成 | P2 |
| S3 | **Keys 术语降维** | "Import Keys / Add your encryption keys" | 说明文字改为"从你的 Switch 导出的 prod.keys 与 title.keys（教程链接）"；附"如何导出 Keys"可展开帮助 | P1 |
| S4 | **Firmware 格式说明** | 只提示选择 zip/文件夹 | 说明文字注明"选择固件 zip 或解压后的文件夹，约 200MB" | P3 |
| S5 | **跳过设置的风险明示** | 双击标题触发隐藏的 skip（发现性差），skip 后无后续提示 | 保留隐藏入口，但在主界面用 banner 持续提示缺失项（已实现 setupReminderBanner），补充：banner 点击直达对应导入 | P2 |
| S6 | **完成页庆祝反馈** | Finish 后直接消失，无任何反馈 | 添加简短完成动画（checkmark 弹出）后进入游戏库 | P3 |

### 3.3 游戏库（GamesListView）

| ID | 优化项 | 现状 | 方案 | 优先级 |
|----|--------|------|------|--------|
| L1 | **空状态强化** | ContentUnavailableView 只有图标+一行字 | 空状态增加主 CTA 按钮（"导入游戏"），点击直达文件选择器；附 2 步引导（"①从 Switch 导出 ROM ②点击导入"） | P1 |
| L2 | **JIT 状态常驻可见** | 仅右上角一个 12pt 小圆点（绿/橙），无文字无解释 | 改为胶囊标签："JIT ✓" / "JIT ✗ 点击了解"，点击弹出诊断面板（原因 + 解决方案 + 跳转 StikDebug） | P1 |
| L3 | **首次进入游戏库的引导** | 无 | 首次（`firstBoot`）显示一次性 coach mark：+ 按钮高亮 + "从这里导入你的游戏"气泡 | P2 |
| L4 | **游戏卡片交互一致性** | 卡片整个可点 + 内部还有 play 按钮（重复热区） | 卡片点击=启动游戏，移除内部重复 play 按钮，改为 hover/长按呼出上下文菜单 | P2 |
| L5 | **搜索与排序** | 无 | 游戏 >10 个时顶部显示搜索框 + 排序（最近游玩/名称/开发商） | P3 |
| L6 | **导入进度反馈** | 大文件复制时无任何进度指示（可能数秒~数十秒卡顿） | 导入期间显示 HUD（"正在导入 xxx.nsp…"），完成后自动刷新列表（已完成弹窗） | P1 |

### 3.4 启动游戏（LaunchGameHandler / LoadingOverlayView）

| ID | 优化项 | 现状 | 方案 | 优先级 |
|----|--------|------|------|--------|
| G1 | **JIT 诊断面板** | 用户点游戏 → 静默尝试 JIT → 失败崩溃（已加弹窗，但仍是"失败后"才告知） | **前置检查**：点击游戏时先检查 JIT，未启用则弹诊断面板（原因：未用 StikDebug 调试 / entitlement 缺失 / 系统版本不支持；动作：打开 StikDebug / 查看教程 / 忽略并继续） | P0 |
| G2 | **启动失败恢复** | 失败弹窗后无后续动作 | 失败弹窗增加按钮："查看日志" / "重试" / "返回游戏库" | P1 |
| G3 | **Loading 状态细分** | 只有"Shader 编译 x/y"一种进度 + 无进度时无限旋转 | 增加阶段文本：翻译缓存加载 → Shader 编译 → 首帧等待；每个阶段有预估时长提示 | P2 |
| G4 | **Loading 可取消** | loading 无任何取消途径（超时 30s 已加，但仍是被动） | 添加"取消"按钮，取消即回游戏库 | P2 |
| G5 | **首次启动前置验证** | 启动前不检查 keys/firmware 是否有效 | 启动前快速校验：keys 可解析 + 固件已安装，失败时给出精准提示（"keys 无效，请重新导入"）而非崩溃后归因 | P1 |

### 3.5 游戏内（EmulationView）

| ID | 优化项 | 现状 | 方案 | 优先级 |
|----|--------|------|------|--------|
| E1 | **菜单入口可见性** | guide 按钮 opacity 0.4，几乎不可见 | 改为半透明悬浮球（opacity 0.85），3 秒无操作自动淡出至 0.3，触摸即恢复 | P1 |
| E2 | **退出措辞** | "Exit (Unstable)" 制造不安 | 改为"退出游戏"，确认弹窗提示"未保存进度将丢失" | P1 |
| E3 | **暂停状态可见** | 暂停时画面冻结，无任何标识 | 暂停时画面中央显示半透明"已暂停"标签 + 恢复按钮 | P2 |
| E4 | **音量/亮度快捷调节** | 无 | HUD 菜单中增加音量滑杆与亮度滑杆 | P3 |
| E5 | **手柄连接提示** | 手柄连接/断开无提示 | 游戏内检测到 MFI 手柄连接/断开时 toast 提示 | P3 |

### 3.6 设置页（SettingsView）

| ID | 优化项 | 现状 | 方案 | 优先级 |
|----|--------|------|------|--------|
| T1 | **术语解释** | "PTC"、"Macro HLE"、"内存管理模式"等无解释 | 每个高级选项添加 info 按钮（ⓘ），点击显示一句话解释 + 影响 | P2 |
| T2 | **危险操作分组** | "清除 Shader 缓存"等破坏性操作与普通开关混排 | 危险操作单独分组，红色标识 | P2 |
| T3 | **设置搜索** | 设置页 1500+ 行，无搜索 | 顶部添加搜索框，模糊匹配设置项名称 | P3 |

## 4. 视觉与交互规范

| 规范 | 现状问题 | 建议 |
|------|---------|------|
| 弹窗一致性 | 混用 SwiftUI `.alert` 与 UIKit `UIAlertController`（`showAlert`），样式不一致 | 统一收敛到 SwiftUI alert/confirmationDialog；`showAlert` 仅作兼容层 |
| 主色语义 | 蓝色用于"导入"、"设置图标"、"play 按钮"等多种语义，绿色同时表示"已导入"和 JIT 圆点 | 定义语义色：主操作=蓝、成功=绿、警告=橙、危险=红，全 App 一致 |
| 触控热区 | guide 按钮、play 按钮等 <44pt | 所有可点击元素热区 ≥44×44pt（iOS HIG） |
| 动效时长 | 无统一规范 | 转场 0.25s easeOut、loading 循环 1s、庆祝动效 0.5s spring |
| 深色模式 | 部分硬编码颜色（Color.black 等） | 全量使用语义化颜色（primary/secondary），支持深色模式一致性 |
